# GUI Mode

Trash-Compactor launches a pywebview-based GUI when started without CLI arguments. The frontend lives in `src/gui/ui/`; Python handles compression work in `src/gui/backend.py` and exposes an API through `src/gui/webview_server.py`.

## Launch Path

1. `main.py` detects an interactive launch (no directory argument).
2. A short CPU benchmark runs; if the machine is too slow, LZX is disabled by default.
3. The parent console window is hidden via `hide_console_window()` so the terminal does not compete with the GUI.
4. `run_gui()` starts the webview server and blocks until the window closes.

If pywebview is missing from a frozen executable, startup fails with a clear rebuild message instead of silently falling back to CLI.

## User Flows

### Folder analysis and compression

1. Choose a folder (or use the folder picker).
2. Adjust settings: minimum savings %, LZX disable, slow-HDD single-worker mode, and binary vs decimal size labels.
3. Press **Analyse** to run the streaming scan pipeline.
4. Review projected savings and the walk/check/entropy timing footer.
5. Press **Compress** to execute the planned batches.

### Quick compression (1-click targets)

Quick compression reuses the same target list as CLI one-click mode (`resolve_targets` in `src/one_click.py`). It analyses each existing target directory in sequence, then compresses where worthwhile.

When running as Administrator, an optional **Compress Windows binaries (CompactOS)** checkbox runs `run_compactos_hidden` in a background thread. Progress and completion appear in a dedicated indicator without opening a separate console window.

## Progress and Feedback

The GUI progress bar moves through approximate phases:

- Walk / scan (indeterminate until check phase begins)
- Per-file eligibility checks
- Entropy sampling
- Compression batches

Status text and the timing footer distinguish walk rate from check rate so displayed throughput matches what the backend is doing.

## Internationalization

On startup, `webview_server.py` injects the active locale dictionary into the frontend boot config via `get_translations()`. `app.js` applies strings through `I18n.t()` for labels, buttons, settings help text, and timing messages.

Locale files live in `locales/*.json` at the repository root and are bundled into frozen builds alongside `src/gui/ui/`.

## Settings Notices

The Settings page includes a Defender / real-time antivirus notice: AV software rescans reads and newly compressed files, which can significantly slow first-run compression on large trees.
