# Native Acceleration

The core scanning and entropy work resides in a small Rust crate (`fast_walk`) exposed to Python through PyO3. Having Rust instead of Python helps dramatically improve directory walking and sampling performance, because those are dominated by syscalls, path manipulation, and small compression probes. Python's interpreter overhead and the GIL made it hard to use all the cores without fighting the language.

## What the Extension Does

- Parallel tree walk. Every file is classified (extension, size, already-compressed check) and the NTFS on-disk size is read in the same pass. Results arrive in batches. A multi-gigabyte tree is never one list in memory.
- Parallel entropy sampling. Largest-N files, dynamic window counts, LZ4 fast path, zlib level-2 probe, mmap for anything big enough to benefit, all on rayon threads. Largest-N selection is folded into a single walk with a bounded candidate list. A directory of a million files never builds a full file list.

The engine is required. `TRASH_COMPACTOR_USE_FAST_WALK=0` is a diagnostic. A serial entropy path still exists for single-worker runs, small trees, and HDD mode. It uses the same sampling budgets. The numbers match.

## Why It Is Fast

A few design choices compound:

The walk avoids allocating a Python object per file or per directory entry during the hot loop. Only small batches of results cross into Python. Inside Rust the work is stolen across a pool of threads using rayon's scope and a simple pending-counter protocol, and newly discovered subdirectories are pushed back onto the shared work list.

Entropy work benefits from the same thread pool plus two cheap wins. First, LZ4 is used as a gate: many real-world incompressible files (already-compressed unclassified archives, media, etc.) are rejected after a few microseconds instead of paying for a full zlib round. Second, files above a couple of megabytes are memory-mapped. The probe does not re-read the same bytes.

Python still owns timers, cancellation, and feeding the GUI. On large trees the effect is higher throughput and lower RAM. Streaming batches replaced the old full-list approach.

## Interaction With the Rest of the Program

Worker counts for the native pools come from the same CPU-topology logic as the rest of the program. The single-worker (`-s`) and LZX-throttling rules still apply. They reduce the native thread count.

The incompressible cache and all the stats recording stay in Python. Rust returns raw numbers and paths. Policy ("is 12% savings good enough?") and the `.db` file stay on the Python side.

The PyInstaller hooks and runtime preload keep the native module importable inside a frozen one-file executable. `TRASH_COMPACTOR_DIAGNOSTIC=1` prints whether the extension loaded.
