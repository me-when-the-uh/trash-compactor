# Size Accounting

Trash-compactor tracks data volume before and after compression, differentiating between logical file size (application view) and on-disk compressed size (NTFS storage). These metrics drive summaries, dry-run projections, and entropy reports.

## Logical vs. compressed size

"Original" size refers to the logical file size. This value matches what Windows displays in file properties and remains constant regardless of NTFS compression.

Compressed size is retrieved via the NTFS API `GetCompressedFileSizeW`. That is the actual bytes used on disk, accounting for cluster rounding. This value confirms compression success and allows calculation of space savings.

A file is considered compressed if its on-disk size is smaller than its logical size.

## Dry-run projections

In dry-run mode, the program projects potential savings without modifying files. Entropy sampling collects data per directory, including file counts, total logical size, and estimated savings based on zlib compression.

For per-directory reporting, the program tracks the total logical size of the subtree, the number of bytes actually inspected, and the projected reduction percentage. Directories are ordered by potential savings, with those below the configured threshold noted.

Global projections accumulate the total logical bytes of candidate directories and the estimated post-compression size. At the end of a dry run, a summary of these projections provides an upper bound on potential disk space recovery.

## Live compression runs

During active compression, the program measures actual results. Running totals cover the logical size of compressed files, their reported on-disk size, and the logical size of skipped files.

The compression executor updates these figures. It records the logical size before compression and the NTFS-reported size afterwards. The difference represents the space saved.

Classification that decides whether a file is skipped happens primarily inside the Rust walker (`fast_walk`), which returns a category together with an on-disk size hint obtained via `GetCompressedFileSizeW`. Those decisions still feed the same totals.

## Directory totals

The summary reports directory sizes before and after compression. The "before" size is the sum of logical sizes for all compressed files, excluding skipped items. The "after" size is the sum of their NTFS-reported compressed sizes, which implicitly accounts for sparse allocation, metadata, and cluster rounding.

The summary derives the final metrics from these totals: original size in megabytes, total space saved, and the overall compression ratio. If no files were compressed, the summary notes that the directory may already be optimized.

## Implementation details

The minimum size test (8 KiB) is applied inside the native walker. Tiny files never even cross into Python during a normal run.

When skipping files where the exact compressed size is unknown, provided size hints are used, then the original size, to keep global totals consistent.

Reports use megabytes or gigabytes depending on magnitude.
