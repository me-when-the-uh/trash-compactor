# Verbose Output

Trash-compactor provides a tiered verbosity system to control the level of detail in its output. This allows users to switch between a clean interactive interface, a script-friendly summary, or deep diagnostic logging for troubleshooting.

## Level 0: Interactive Mode (Default)

When no verbosity flag is provided, the program defaults to **Level 0**. This mode is designed for human interaction in a terminal.

It displays a dynamic progress timer during the file scanning phase and progress bars during the compression stages. These UI elements update in place to show the current status without flooding the console history.

At the end of the operation, a concise summary of the compression results is printed. DirectStorage game directories (`dstorage.dll` / `dstoragecore.dll`) are listed by path even at this level, because they are excluded from the plan and from the savings estimate.

## Level 1: Scripting & Entropy Mode (-v)

**Level 1** disables the interactive UI elements (progress timers and progress bars), making it suitable for automated scripts or logging to a file.

In addition to the final summary, this level now includes detailed reporting on the entropy analysis and directory filtering process. It logs specific decisions made by the entropy filter, such as which directories were skipped because their estimated savings fell below the configured threshold. User-excluded directories are listed here as well.

It also adds warnings for files that were successfully processed by the compression tool but did not result in any size reduction. These files are reported with a warning message and are **excluded** from the final compression statistics to provide a more accurate picture of effective compression.

## Level 2: Progress Updates (-vv)

**Level 2** includes everything from Level 1 and adds per-stage progress updates so you can follow the run as it moves through scanning, entropy analysis, and compression.

## Level 3: Debug Mode (-vvv)

**Level 3** enables full debug logging. This is the most verbose mode and is intended for developers or deep troubleshooting.

It logs every significant action: per-file compression outcomes, the full set of entropy samples taken for every directory, the exact reason each file or directory was skipped, and the system directories that were protected. In dry-run mode the final report emits every entropy sample rather than only the ones that passed the savings threshold, which is useful when tuning the estimator itself.

## Log File Mode (`--log-file`)

`--log-file` is for scheduled or scripted runs where stdout may be discarded. With no value, the log is written to `trash-compactor.log` in the cwd. With a value, the log is written to that path. The log is truncated at the start of every run.

The log mirrors the end-of-run stdout blocks: header, mode and target, effective settings, dry-run or compression summary, performance summary, per-algorithm breakdown, skipped directories (at verbosity >= 1), errors, and an exit-code footer.

On a non-interactive console, prompts that would block return documented defaults, `confirm_hdd_usage` refuses to proceed without `--yes`, and 1-click mode skips the 300-second countdown. CompactOS is opt-in via `--compactos-always` and does not run on a non-interactive console; only the interactive CLI prompts before starting it.
